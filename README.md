> Combine Chinese radicals. Summon the beast hiding inside the character.
> 一个游戏，**14 个部首，12 只兽**。用来验证**不会中文的海外用户愿不愿意靠"试"来玩汉字合成**。
>
> v0.2 变化：从 21 部首 / 30 只**缩到 12 只**用于首轮验证（理由见下）。

## 跑起来

```bash
cd hanzi-beasts
python3 -m http.server 8123
# 打开 http://127.0.0.1:8123/
```

必须走 HTTP（用了 ES modules，`file://` 会被 CORS 挡住）。

## 为什么是 12 只，而不是 30 只

首轮验证只验证一个假设：**不会中文的人愿不愿意靠试来玩汉字合成**。
30 只里 25 只是同质几何占位，Reddit 用户看到会判定"半成品"，直接污染结论。
12 只里 5 只手绘（42%），视觉密度够，且不至于让人一眼看出是未完成品。

**名单是手工挑的，不是「Tier1 前 12 只」。** 原因：森（木×3）和 仙（人+山）是
Tier2，但它们是**手绘兽**——按 tier 截断会把刚画好的两张图一起砍掉。

挑选三原则：
1. 5 只手绘全在（美术不能白画）
2. 其余挑「一眼能猜中」的会意字：林 休 看 相 尖 炎 岩
3. 部首尽量共用 —— 14 个部首养 12 个配方

**代价（要如实记录）**：随机试的命中率从 13%（21 部首 / 30 配方）降到
**11.4%**（14 部首 / 12 配方）。降幅比"30→12"的直觉小，因为同时砍掉了部首噪音，
但仍然是负向。靠「差一点」的分级反馈来补偿搜索效率。
如果实测首次成功耗时超过 90 秒，优先怀疑这个，而不是怀疑玩法。

**扩容回 30 只**：把 `src/data.js` 的 `ACTIVE_IDS` 换成
`RECIPES.map(r => r.id)`，然后重跑 `node tools/dump-svg.mjs` 刷新 `fonts/chars.txt`
并重新子集化字体。

**以注册商实时价为准，别按 .com 的预算估。**

## 美术自检（重要）

我（AI）看不到渲染结果，画 SVG 是盲画，图层覆盖类的错自己发现不了。
`tools/artcheck.py` 用采样像素代替眼睛：导出 SVG → headless Chrome 截图 → 检查眼睛坐标的颜色。
判据：眼白处 `min(rgb)>180`、瞳孔处 `max(rgb)<110`、指定装饰在指定坐标。

```bash
python3 tools/artcheck.py     # 需要 pillow + node；当前 5 只手绘全部 PASS
```

它抓到过两个肉眼绝对看不见的问题：囚的橙色爪子整个盖住眼白（看起来像红眼睛）、
仙的寿眉太细被描边吃光。**每新增一只手绘兽，必须往脚本里的 EYES/SPOTS 表加坐标。**
